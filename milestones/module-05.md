# Module 5 - Deployed Full-Stack Application

C3 - End-to-End AI-Assisted Application Delivery. **C3.1-C3.5 | Application evidence; defense follows in Module 6.**

Complete the second backend feature, build React from your frontend spec and deliver a reproducible full-stack TraceLens application.

This is the optional TraceLens capstone track. Follow PromptLab's demonstrated methods independently; no TraceLens walkthrough is required. Continue your own repository rather than restarting from another starter.

## Work and evidence

1. Commit specs/frontend.md before React code, naming screens, components/props, routes, state and async behavior.

2. Implement the remaining feature and additional backend endpoints test-first; run tests against deployed configuration.

3. Verify real dashboard/project/trace journeys, correct pagination, and both evaluations and alert rules through the UI.

4. Provide loading, empty and visible error states; document a reproducible deployment or full-stack container run.

5. Record honest scaffold-to-first-new-endpoint timestamps, plan and blockers. C3.5 timing requires calibration; see the criterion text.

## Task detail

Expand specs/frontend.md before generating the UI. Initialize React/Vite locally using a compatible supported Node LTS version, then commit the package lock and document the versions and commands you verified. Remove unused template scaffolding. Every specified component gets its own module; explain your folder principle in one sentence.

Implement the other backend feature with genuine failing-test commits first, plus any required UI endpoints. Both evaluations and alert rules must be complete. Record the Module 5 backend increment from scaffolding to its first passing new endpoint, along with your plan and blockers. The original four-hour figure is unvalidated: calibration and a published versioned budget are required before timing can cause Not Yet. Missing calibration does not automatically earn Met.

Verify dashboard stats from the actual API; project create, rename and confirmed delete with the chosen orphan policy; combined project/model/status filters, search, correct page counts and trace detail. Drive evaluation entry/list/project summary and alert-rule create/list/delete/evaluate through the UI. Test a new empty project and API failures with visible feedback, plus loading, form validation, keyboard access and responsive layout.

Use real API data for final checks. Document API URL/proxy and CORS settings. Provide docs/deployment.md with every setup step, variable, secret-handling approach, data lifetime and seed procedure. A documented full-stack container run is acceptable; paid hosting is not required. Verify from a clean clone and against the deployed configuration, not only a local in-process test client.
