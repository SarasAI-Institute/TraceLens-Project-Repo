# Frontend - learner specification brief

Complete and commit this in Module 5 **before React implementation**.

Specify screens, each component's responsibility/props, API routes consumed, state ownership, loading/empty/error behavior and the one-sentence folder organization principle. Each specified component must be its own module. Keep UI and backend concerns separate.

Required journeys use the real API: dashboard with project stats; create, rename and confirmed delete with the chosen trace policy; trace filters by project/model/status, combined search, correct pagination and trace detail (prompt, response, tokens, cost, latency, tags); evaluation entry/list/project summary; alert-rule create/list/delete/evaluate and visible trigger results. Both backend features must be usable in the final UI.

Specify validation feedback, keyboard use and responsive layout. Define deployment API URL/proxy and CORS behavior, including a new project with no traces and an API that is unavailable. Mocks may help during development but cannot establish final end-to-end competence.
